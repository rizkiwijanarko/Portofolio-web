## Overview

**Ningsih** is a proactive mobile SaaS that acts as an intelligent digital chief of staff. Rather than forcing users into rigid boards and complex nested menus, Ningsih turns natural conversation and voice notes into structured daily momentum — managing calendars, tracking habits and milestones, recording personal context, and orchestrating routines.

The project originated as an autonomous Telegram bot prototype and has evolved into a full-stack, multi-tenant mobile product backed by a reactive serverless backend and a low-latency agent tool execution engine.

## The Problem

Busy professionals, independent builders, and ADHD minds frequently struggle with **executive dysfunction, time blindness, and calendar overload**.

Traditional productivity tools exacerbate this friction:
- **High initiation overhead**: Creating a task requires filling forms, setting dates, tags, and priorities — the exact cognitive friction that causes task paralysis.
- **Vague, overwhelming goals**: Large ambitions like *"Launch SaaS"* or *"Write client proposal"* lack actionable next steps.
- **All-or-nothing streak guilt**: Missing a single day wipes out a habit streak, causing users to abandon the tool entirely.
- **Disconnected context**: Calendars, to-do lists, habit trackers, and notes live in separate silos that don't communicate.

## System Architecture & Agent Data Flow

Ningsih is designed around a reactive, serverless architecture that connects an Expo/React Native mobile client to a real-time Convex backend and external AI inference endpoints.

### Architectural Layers

1. **Client Layer (Mobile Application)**: Built with Expo SDK 57 and React Native using NativeWind (Tailwind CSS) and the Ember Studio design system. Uses reactive Convex query hooks (`useQuery`, `useMutation`) for instant, optimistic UI updates.
2. **Backend Layer (Convex Serverless)**: Real-time relational document store managing multi-tenant data (users, goals, milestones, tasks, activities, calendar events, memories, and routines) with strict tenant isolation.
3. **Agent Intelligence Engine**: Fast LLM reasoning and unified tool dispatcher executing 10 atomic tools, validating arguments, and performing structured state mutations.
4. **External Services**: Two-way Google Calendar OAuth sync, OpenAI Whisper audio transcription, Clerk authentication, and RevenueCat subscription webhook validation.

### Agent Tool Execution Mapping

Instead of returning plain text advice, the agent translates conversational requests into transactional backend mutations:

| User Request Intent | Agent Tool Invoked | Real-Time State Mutation |
| :--- | :--- | :--- |
| *"Add gym at 4 PM after client call"* | `scheduleEvent` | Verifies Google Calendar availability, creates event, projects daily agenda |
| *"I'm overwhelmed starting this proposal"* | `suggestMicroTask` | Generates 3-tier difficulty decomposition with 2-min initiation micro-step |
| *"I want to launch my MVP next month"* | `alignGoal` / `manageGoal` | Socratic goal refinement &rarr; 3-tier milestone cascade in database |
| *"Distracted for an hour on YouTube"* | `logActivity` | Logs activity, starts 5-min gentle re-entry timer without streak penalties |
| *"Remember I prefer deep work mornings"* | `rememberContext` | Upserts long-term user memory record applied in future morning briefings |

## Key Engineering Decisions & Trade-Offs

- **Real-Time Reactive State (Convex) over REST Polling**:
  - *Context*: Calendar updates, task completions, and agent actions must reflect instantly across all screens.
  - *Decision*: Adopted Convex reactive subscriptions. Mutations trigger automatic delta updates to all active queries, eliminating polling overhead and stale client state.
- **DeepSeek V4 Flash for Low-Latency Tool Calling**:
  - *Context*: Mobile conversational interfaces require sub-second responses for tool execution.
  - *Decision*: Deployed DeepSeek V4 Flash via OpenRouter for high-throughput, low-latency reasoning and structured tool calling, backed by an OpenAI API fallback mechanism.
- **Server-Authoritative Entitlements & Security (Clerk + RevenueCat)**:
  - *Context*: Freemium tiers (Free vs. Plus) and Google Calendar tokens must remain tamper-proof.
  - *Decision*: Authorization and tier gating are strictly enforced on serverless backend functions and validated via webhooks. Sensitive tokens are never stored on the mobile device.
- **Deterministic 2-Minute Micro-Task Logic**:
  - *Context*: Standard AI task breakdowns often output multi-hour steps that still induce paralysis.
  - *Decision*: Constrained prompt schemas to enforce a 3-tier progressive structure where Tier 1 must be executable in under 2 minutes.

## Hard Engineering Challenges

### Two-Way Google Calendar Conflict Resolution & RRULE
- **The Challenge**: Merging third-party Google Calendar events with in-app scheduled tasks without causing race conditions or duplicate entries during offline-online transitions.
- **Solution**: Implemented a two-tier synchronization pipeline: 15-minute background cron sync paired with immediate on-write write-through projections. Evaluated recurring event rules (RRULE) server-side and maintained optimistic client caches.

### Low-Latency Native Audio Processing
- **The Challenge**: Recording audio on native devices and streaming it to transcription models without freezing the JS event loop or delaying user feedback.
- **Solution**: Utilized `expo-audio` with direct buffer streaming to serverless Whisper actions, immediately chaining transcript output into the DeepSeek tool dispatcher in a single asynchronous transaction.
